## 当前范围（2026-11-12 收紧）

入口以 `.scratch/remote-projects/key-screens.eficy` 的“添加项目 → 选机器 → 选目录”为参考，无远端机器时直达原本机目录。核心是项目关联、共享项目/会话列表、远端对话、机器隔离和恢复；已有文件、Git、桌面终端、预览只适配远端作用域。

用户最新要求覆盖旧稿：不新增手机终端，不增加独立 Provider/插件/MCP 配置浏览面板。移动端复用现有项目卡片、会话行和菜单；不带入桌面缩略导航、拖拽柄、复选框及常驻管理按钮。历史验收材料中的手机终端证据仅作历史记录，不能据此恢复入口。

组件分层沿用 ViewModel + 展示 Adapter + 操作描述：Query 层拥有远端读取、作用域及响应校验，model 拥有提交与导航编排，视图复用共享原语。优先使用 TanStack Query、ReactUse 已有能力；性能只接受无损优化，未测量门槛保持未验证。

## 执行目标与本机助理（后续扩展）

项目与会话引用携带权威实例坐标，资源所属实例与访问连接分别表达。远端引用使用
`target: {hubId, hostId, instanceId}`，另附原始目录及会话 ID；`instanceId` 来自已鉴权的
目标能力端点，Hub 持久化连接与实例的绑定。凭据轮换、连接重建不改变资源归属；同一
连接改指另一实例时拒绝执行，保留旧引用与快照。各条 SSH/Relay 连接的授权与缓存仍独立。

本机助理可以使用 Hub 已有授权发现远端项目、读取会话、创建和继续对话、监听结果及
执行会话级操作。候选、模型/agent 配置、执行、卡片与导航使用同一目标；远端失败不得
回退本机同名目录或会话。后台任务拥有独立、可释放的连接需求，最后窗口退出不取消
仍有效的助理监听；没有窗口或任务需求时仍释放远端资源。

用户允许助理自己的公开回复和滚动摘要保存在 Hub。远端原始消息与工具读取结果保持
临时使用，不进入 Hub 的会话缓存、内容索引或助理历史。这是本机助理操作远端资源，
不改变助理运行位置，也不引入远端助理页面嵌入。

## 术语

- **Hub**：当前窗口所连接的 Yuri 实例，必须是一台 PC（Electron 桌面端内置的 server）。Remote Project 的引用、远端连接、凭据和会话摘要索引都由 Hub 持有。窗口切换实例后，被切换到的那台实例就是新的 Hub。
- **Remote Host**：Hub 已经配置好、能够到达的另一台 PC 上的 Yuri 实例。来源有三种：SSH 实例、Relay 配对设备、直连 `apiUrl` 设备。用 `hostId` 标识，复用现有的桌面 host 身份。
- **Remote Project**：归属于某个 Remote Host 的项目。在 Hub 上的身份是 `(hostId, path)`；本机项目的 `hostId` 为空。
- **Location Key**：`(hostId, directory)`，所有与目录绑定的状态都以它为 key。本机的 Location Key 序列化后与现有的 directory key 保持一致。
- **Host Connection**：Hub 到某个 Remote Host 的连接实体，状态包括 `idle | connecting | connected | degraded | offline | unauthorized | incompatible`。
- **状态订阅**：Hub 对 Remote Host 保持的轻量实时订阅，只接收会话状态、标题和会话列表变更，不接收消息流。
- **内容订阅**：打开某个远端会话时，按需建立的消息流与工具输出订阅。
- **整窗切换**：现有的实例切换能力，把整个窗口（桌面或手机）切换到另一台实例，此后完全以那台实例的 DB 为准。

## Problem Statement

我的一台 PC 已经连接了好几台其他机器（通过 SSH、Relay 或直连）。现在要管理那些机器上的项目和会话，只能整窗切换过去。切过去之后，本机的会话就看不到了；同一时间只能看一台机器；也无法知道哪台机器上有会话正在运行。不同机器上的同名项目也不能同时出现。手机也是一样，一次只能看一台实例，看不到这台实例连接的其他机器上的情况。

## Solution

两种模式并存，互不冲突：

- **聚合**：在当前窗口里新建项目时，可以先选一台 Remote Host，再选它上面的目录，得到一个 Remote Project。它和本机项目一起显示在侧边栏，带远端角标；hover 时显示来源机器和连接状态。会话真正运行在远端，远端是唯一权威。Hub 只同步会话列表和运行状态，不存聊天内容。打开远端会话时自动连接，可以使用和整窗切换后一样的项目和会话级能力：对话、权限、文件、git、终端、预览等。
- **整窗切换**：保留现有能力，用来管理那台机器本身（Provider、插件、MCP、设置等），以及直接以那台机器的 DB 为准工作。

手机不自己做聚合。手机连接（或切换到）哪台 PC 实例，就读取那台实例的聚合结果，体验和桌面一致。

## User Stories

### 机器选择与项目创建

1. 作为桌面用户，我想在“添加项目”时先选择一台机器，以便在那台机器上打开或创建项目。
2. 作为桌面用户，我想默认选中本机，并且只有存在 Remote Host 时才出现机器选择，以便只用本机的人完全感受不到这个新步骤。
3. 作为桌面用户，我想在机器列表里看到每台机器的连接状态（在线、离线、需要授权、版本不兼容），以便知道现在能不能选它。
4. 作为桌面用户，我想从 SSH 实例、Relay 配对设备和直连设备中任意选择一台作为 Remote Host，以便复用已有的连接。
5. 作为桌面用户，我想在选中远端机器后浏览它的目录树，以便像选本机目录一样选远端路径。
6. 作为桌面用户，我想在远端机器上新建一个空目录作为项目，以便从零开始。
7. 作为桌面用户，我想在 Hub 上创建 Remote Project 时，项目也同时登记到远端机器自己的项目列表中，以便整窗切换到那台机器时看到的是同一个项目。
8. 作为桌面用户，我想在远端机器上已经有同路径项目时直接关联它，而不是创建重复项目，以便两边始终是同一份项目。
9. 作为用户，我想让两台机器上同名、同路径的项目同时出现在侧边栏，以便分别管理。
10. 作为用户，我想修改 Remote Project 的名称、图标、颜色时写回远端，以便两种模式下看到的一致。
11. 作为用户，我想移除 Remote Project 时只删掉 Hub 里的引用，不影响远端的项目、文件和会话，以便放心清理。
12. 作为用户，我想在远端机器删除了项目后，在 Hub 上看到“远端已移除”的标记，由我决定清理还是重新添加，以便不会被静默删除。
13. 作为用户，我想在 Remote Host 被移除或凭据被撤销后，仍然能看到它名下的 Remote Project，并显示“机器不可用”，以便决定重新授权还是移除。
14. 作为用户，我想在远端 Yuri 或 OpenCode 版本过低时，得到明确的不兼容提示和升级引导，以便知道该怎么处理。
15. 作为整窗切换到 B 的用户，我想在 B 自己已经配置了到 C 的连接、且 C 是一台 PC 时，在这个窗口里创建 C 上的 Remote Project，以便由 B 作为 Hub 管理 C。
16. 作为整窗切换到 B 的用户，如果 B 没有到某台机器的连接，我想看不到那台机器作为可选项，以便不会误以为可以借用本机的连接。

### 侧边栏与标识

17. 作为用户，我想让 Remote Project 在侧边栏有统一的远端角标，以便一眼区分本机和远端项目。
18. 作为用户，我想 hover Remote Project 时看到机器名称和连接状态，以便知道它来自哪台机器、现在是否可用。
19. 作为用户，我想在 Remote Project 下看到会话列表、运行状态和未读标记，体验和本机项目一致，以便统一管理。

21. 作为用户，我想在折叠的项目上也能看到“有会话正在运行”的指示，以便不展开就知道哪台机器在干活。

25. 作为用户，我想让 Remote Project 在 Hub 侧边栏里的位置和折叠状态只存在 Hub，以便不影响远端机器自己的布局。

## Implementation Decisions

### 两种模式与角色

- 聚合和整窗切换并存。聚合依赖 Hub 自己的 Yuri DB，里面记录的是 Hub 已连接的设备和 Remote Project 引用；整窗切换则完全以目标实例的 DB 为准。两者不共享状态，也不互相替代。
- 只有 PC（Electron 内置的 server）能当 Hub，Remote Host 也必须是 PC。手机只当客户端，不自己做聚合。手机切换到哪个实例，就读取哪个实例的聚合结果。
- 窗口整窗切换到 B 后，B 就是 Hub。B 只能使用自己已经配置好的 Remote Host；创建和连接的逻辑都在 B 上执行，不借用客户端本机的连接或凭据。
- 只做一级聚合：Hub 不会把 Remote Host 自己聚合的 Remote Project 再聚合一次。A、B 互相聚合时，各自只显示对方的本机项目。
- 支持的运行时：Electron 桌面和 Capacitor 手机。手机网页与 VS Code 显式不支持，Remote Project 入口不出现，或显示不支持提示；共享契约中要把这一点写成显式分支。

### 能力下沉到 Hub server

- 目前 SSH 连接管理、设备列表存储在 Electron 主进程和设置文件里，Relay 隧道客户端在渲染进程里，Yuri server 自己还没有主动连接远端的能力。需要新增一个由 server 拥有的 **Remote Host Gateway** 模块：负责建立和维护到各个 Remote Host 的传输（SSH 隧道 / Relay E2EE 隧道 / 直连 + client token），对外只暴露“按 hostId 发请求、建立实时订阅”的接口。
- Electron 主进程仍然负责 SSH 的交互式配置、钥匙串和权限弹窗等原生能力，只通过 server 注入的回调接口把连接能力提供给 Gateway。不新增传输协议，复用现有的 SSH / Relay / 鉴权模块。
- Gateway 是唯一知道凭据的地方，凭据不出现在任何 API 响应、事件和日志中。

### 数据归属

- **项目**：双写。在 Hub 上创建 Remote Project 时，先确保远端机器的项目列表里有这个项目（已有同路径则关联），再在 Hub 记录一条引用：`hostId`、远端项目 ID、路径。名称、图标、颜色等元数据以远端为准，Hub 只缓存用于离线显示。Hub 独有的只有本窗口的布局：在侧边栏中的位置、折叠状态。
- **会话摘要**：远端为权威。Hub 在每次连接完成后，以及收到状态订阅事件时，把远端项目下的会话摘要（ID、标题、时间、父子关系、状态、置顶、归档、未读）同步进自己的 session index，按 `hostId` 分区。
- **会话内容**：Hub 的任何持久化存储都不保存远端会话的消息和 parts，Hub 的 transcript 缓存对远端会话一律跳过。客户端的 IndexedDB 可以缓存远端会话内容，只作为加速，规则和本机会话相同：以远端为准，过期内容被覆盖。
- **会话整理信息**：置顶、文件夹、排序、归档、已读/未读、标题，都写回远端机器，Hub 只镜像。写入失败时回滚本地乐观状态并提示，不保留只存在于 Hub 的分叉状态。
- **移除与失效**：在 Hub 移除 Remote Project 只删引用。远端删除项目后，Hub 将其标记为 `remote-removed`，等待用户处理，不自动删除。Remote Host 被删除或撤销后，名下的 Remote Project 标记为 `host-unavailable`。
- **配置**：远端对话的模型、agent、Provider、MCP、插件使用远端自己的配置，候选复用现有对话入口；配置浏览与管理通过整窗切换完成，不新增独立面板。配置同步不在本期范围内。

### 数据模型

- 项目实体新增可选的 `hostId`、`remoteProjectId`、`remoteState`（`ok | remote-removed | host-unavailable`）。项目身份由 `path` 改为 `(hostId, path)`；迁移后旧数据的 `hostId` 为空。
- UI 中所有以 directory 为 key 的状态（sync child store、会话归属索引、侧边栏会话窗口状态、草稿 DraftKey、文件 tab、query key、会话顺序 scope key）统一改为以 Location Key 为 key。本机的 Location Key 序列化结果必须与现有 key 一致，这样本机用户的持久化状态无需迁移就能命中。
- Session index 的 `runtime_key` 承载 `hostId`，多个分区并存，分区之间互不覆盖、互不清理。
- Host Connection 的状态保存在内存中；`lastConnectedAt`、`lastSyncedAt`、`lastError`（不含凭据）持久化，用于离线显示。

### Hub API 契约

- `GET /api/hosts`：返回 Hub 可聚合的 Remote Host 列表，包括显示名、来源类型、Host Connection 状态、版本和能力摘要。手机网页、VS Code 和非 PC 的 Hub 返回明确的“不支持”标记。
- `/api/hosts/:hostId/*`：把 OpenCode v2 API 和 Yuri 自有能力（文件、git、终端、预览、会话顺序与文件夹、已读状态、项目元数据）代理到对应的 Remote Host。本机仍然走现有路径，不加前缀。
- Host Connection 状态事件和远端状态订阅事件，复用客户端到 Hub 的现有实时通道多路复用，不为每个 host 新开客户端 socket。打开远端会话时，内容订阅也在同一条通道上复用。
- 服务端对每个 `hostId` 请求都做校验：host 存在、请求方客户端已配对授权、host 属于本 Hub。被拒绝时返回明确的错误码，不返回空成功。
- 远端能力不足时，返回结构化的 `incompatible` 错误（包含最低版本要求），由 UI 展示原因。
- 终端、预览、localhost 链接等流式或长连接能力，复用现有的 realtime proxy 和 Relay 转发机制，按 `hostId` 路由。

### 连接生命周期

- **状态订阅**：只要 Hub 上存在 Remote Project，并且至少有一个客户端在线（Hub 窗口自己，或通过 Hub 连接的手机/桌面），Hub 就对每台相关的 Remote Host 保持一条状态订阅。没有任何客户端在线时，所有远端连接都断开。
- **内容订阅**：只有当客户端正在查看某个远端会话，或者使用终端、文件监听等能力时才建立；最后一个使用者离开后，在宽限期内释放。
- 运行状态来自远端的实时通道，不从持久化历史推断。连接断开时，“运行中”降级为“状态未知（最后已知：运行中）”。
- 重连使用带抖动的指数退避，上限有界；网络恢复或客户端回到前台时立即尝试一次。重连成功后，先同步会话摘要，再为当前打开的会话补拉消息，最后恢复增量。
- 单台 host 的超时、认证失败、卡死，不得阻塞其他 host 的连接、索引刷新、请求或 UI 渲染。

### Session index 刷新

- 刷新调度从单 runtime 扩展为按 host 分队列。每个 host 沿用现有的页数和 payload 预算；各 host 之间公平轮转；慢请求有超时，不占用其他 host 的槽位。
- 会话内容、子会话和消息变更仍然优先于索引刷新，并且这一优先级跨 host 生效。
- 离线或拉取失败时保留上一次快照并标记 `stale`，绝不写入权威空列表。缺失目录清理只对本机生效，远端目录从不用 Hub 的文件系统作证据。

### UI

- 新增 **Host Runtime Registry**，取代单例 runtime endpoint 作为数据访问入口：按 Location Key 解析出对应的 OpenCode client、runtime fetch 和实时订阅。本机条目就是现有的 runtime，行为不变。整窗切换仍然通过现有机制替换整个 registry 的根。
- 添加项目流程：选择机器（默认本机，只在有可用 Remote Host 时出现）→ 浏览目录（远端经 Hub 代理）→ 创建或关联。
- 侧边栏：Remote Project 显示远端角标；hover 显示机器名和连接状态；离线时显示“离线 · 最后同步于 X”；另外显示 `remote-removed` 和 `host-unavailable` 两种状态。角标和状态只订阅该 host 的连接状态字段。
- 输入框：远端项目显示机器 chip，本机不显示；离线时禁止发送并说明原因，保留输入和草稿。模型、agent、Provider、命令、skills、文件引用的候选都从该 Location 所属的 host 读取，并且只在 picker 打开时按需拉取。
- 只在本机有意义的操作，在远端项目中隐藏或禁用并说明原因。
- 所有新增文案走 i18n；按钮遵循 shared neutral `Button` 规范；进度和状态样式沿用现有 design token。

### 通知

- 每个 Yuri 实例暴露一个稳定的实例身份（复用 relay `serverId` 或配对身份）。
- 桌面端在多个窗口之间按 `(实例身份, sessionId, 事件)` 去重，同一事件只通知一次；点击通知时按 Location Key 导航。
- 手机推送由会话所在的机器发出，Hub 不转发远端推送。已知限制：手机如果没有直接配对远端机器，就收不到它的推送，只能在打开 Hub 视角时看到状态。

### 测试 seam

只设两个，尽量高层：

1. **Hub 契约 seam（主 seam）**：启动真实的 Hub server，配合 1~N 个 fake Remote Host（延迟、断线、错误、版本、卡死都可以控制），通过 `/api/hosts/*` 和实时通道断言外部行为。覆盖连接生命周期、状态订阅与内容订阅、索引分区、双写与写回、内容不落 Hub、权限校验、凭据不外泄、故障隔离。
2. **UI Host Runtime Registry seam**：在 happy-dom 中为 registry 注入 fake Hub 响应，断言侧边栏、输入框和会话视图的渲染结果以及操作计数。现有的 sync 和侧边栏测试只需把 key 换成 Location Key。

## 性能验收（必须全部满足，任意一项未达标都不能交付）

### 测量规范

- 计时指标在生产构建上测量，记录设备、Electron / iOS 版本、构建号和数据集；改造前后在同一配置下对比。
- 单元测试只断言确定性的操作计数（selector 调用、遍历、请求数、订阅数、写入行数），不断言毫秒数。毫秒预算由 Electron 和 iOS 实测覆盖。
- **标准数据集 L**：1 台本机 + 5 台 Remote Host；共 50 个项目，其中 10 个是跨机器同名；共 5,000 个会话摘要；有 5 个会话同时在流式输出，分布在 3 台机器上。
- **标准网络画像**：LAN 直连（RTT ≈ 5ms）、Relay（RTT ≈ 80ms）、弱网（RTT 300ms，1% 丢包）。

### P0：只用本机的用户零回退

1. 没有 Remote Project 时，启动阶段新增的网络请求、实时订阅、定时器和轮询都为 0（用计数断言）。
2. 没有 Remote Project 时，冷启动到侧边栏首帧、到第一个会话 transcript 可见的耗时，相对基线回退 ≤ 5%（P50 和 P95 都要满足，每项至少测 20 次）。
3. 现有性能测试全部通过且阈值不放宽，包括：侧边栏项目列表、侧边栏操作、transcript SSE、输入框 closed picker 操作计数、avatar performance。

### P1：侧边栏与冷启动（数据集 L）

4. 冷启动时，侧边栏直接从 Hub 的 SQLite 快照渲染远端项目和会话，不等待任何 Remote Host 的网络响应。所有 Remote Host 都离线时，侧边栏首帧耗时相对“仅本机、同等会话数”的基线回退 ≤ 10%。
5. 某台 host 的一次会话状态或标题事件，只能让该 host 对应的项目 bucket 重新计算；其他 host、其他项目的 selector 重算次数为 0，未受影响的项目和会话对象保持引用不变（用操作计数和引用相等断言）。
6. 5 个会话并发流式输出时，侧边栏的结构列表（排序、分组）不会被 token / delta 频率的字段触发重算；每秒结构重算次数不超过运行状态真正发生变化的次数。
7. Host Connection 状态变化只重渲染该 host 的角标和对应行，不重渲染整个项目列表。

### P2：输入框（数据集 L，5 路并发流式）

8. 满足输入框响应性契约：同步输入处理 **P95 ≤ 16ms**，并且**没有由输入引起的 ≥ 50ms 主线程任务**。每个场景至少 50 次输入事件，覆盖本机项目和远端项目、中文 IME、粘贴、撤销。
9. 机器 chip 和离线状态的计算不进入按键路径：连续输入期间，host 连接状态 selector 调用次数为 0，模型 / agent / Provider 目录枚举次数为 0（扩展 closed picker 测试，在 300 条目录规模下断言）。
10. 远端 host 的目录（模型、命令、文件候选）只在 picker 打开时按需拉取并缓存；打开 picker 不阻塞文本回显。

### P3：远端会话的打开与实时性

11. 打开一个已经有客户端缓存的远端会话时，缓存的 transcript 在 **≤ 100ms** 内可见（与本机会话的预算相同），不等待连接。
12. 打开远端会话到展示最新的权威状态（状态订阅已在线，需要新建内容订阅）：LAN **P95 ≤ 1s**，Relay **P95 ≤ 2s**。Host 连接为 `idle` 需要冷建连时：LAN **P95 ≤ 1.5s**，Relay **P95 ≤ 3s**，SSH 隧道 **P95 ≤ 5s**。
13. 远端流式输出经过 Hub 代理时，相对于网络 RTT 额外引入的延迟 **P95 ≤ 50ms**。
14. 断网后 **≤ 2s** 显示离线或重连状态；网络恢复后 **≤ 5s** 内恢复连接并补齐消息，补齐结果无重复、无缺失、顺序正确。
15. 弱网画像下，transcript 滚动和输入框仍然满足 P2 的预算（网络慢不能变成主线程卡顿）。
16. 远端会话在其他窗口或手机上启动后，Hub 侧边栏在 **≤ 2s** 内显示运行中（状态订阅在线，LAN 和 Relay 都要满足）。

### P4：Hub 资源占用

17. 没有任何客户端在线时，Hub 到所有 Remote Host 的连接数、请求数和定时器都为 0（观察 10 分钟）。
18. 有客户端在线时，每台 Remote Host 只保持 **1 条**状态订阅；单条状态订阅的 Hub 常驻内存增量 **≤ 10MB**；5 台 host 都在线但没有会话活动时，Hub 进程 CPU **< 0.5%**（观察 5 分钟）；状态订阅期间不发生周期性的全量拉取。
19. 内容订阅同时打开的数量有上限（默认 8，可配置），超出时按最近使用淘汰。淘汰不影响状态订阅和运行状态的可见性。每个活跃内容订阅的 Hub 内存增量 ≤ 30MB。
20. 单台 host 超时、卡死或返回慢响应时，其他 host 的索引刷新和会话请求 P95 回退 ≤ 10%（用 fake host 注入 30 秒无响应来验证故障隔离）。
21. 跨 host 的索引刷新总预算有界：任一时刻同时进行的上游刷新请求数 ≤ 现有单 runtime 上限 × 2，单台 host 不超过现有单 runtime 上限。
22. Hub 持久化存储中，远端会话的消息和 parts 行数为 0（契约测试断言，包括 transcript 缓存）。

### P5：移动端

23. 手机到 Hub 只保持**一条**实时连接，远端 host 的事件在这条连接上多路复用；手机打开的 socket 数量不随 host 数量增长。
24. App 进入后台后，由手机触发的内容订阅在现有后台宽限期内释放；回到前台时，可见的远端会话在 **≤ 2s** 内（Hub 已连接）刷新到最新状态。
25. 在数据集 L 下，手机会话列表滚动时没有 ≥ 50ms 的长任务，与本机同等会话数的基线相比不回退。

### 证据要求

- 每项验收都要在 PR 或工单中附上：命令或脚本、数据集、环境、改造前后的数值（P50 / P95 / max）。
- 没有实测的 runtime 必须显式列为“未验证”，不能用其他平台的结果代替。
- 未达标的项保持“未解决”，不能作为功能取舍被接受。只接受无损优化，不通过降低功能或数据完整性来换取性能。

## Testing Decisions

- 好的测试只验证外部行为：Hub API 的响应与事件、侧边栏和输入框的渲染结果、确定性的操作计数。不测试内部数据结构或私有函数。
- **Hub 契约测试**（`@yuriai/web`）：真实 Hub 加上 fake Remote Host，覆盖以下内容。可参考的现有测试：session index 的 sync-runtime 与 routes 测试、relay host-client 重连测试、session-folders routes 测试。
  - 连接状态机；状态订阅随客户端在线而保持、全部离线后断开；内容订阅按需建立和释放
  - 重连补齐；索引分区隔离；离线快照不清空
  - 双写与关联；整理信息写回以及写回失败时回滚
  - `remote-removed` 和 `host-unavailable`
  - 权限拒绝；凭据不出现在响应和日志中
  - 未配对的 SSH 不走 Relay；一级聚合不递归
  - 内容不落 Hub（P4-22）；故障隔离（P4-20）；资源计数（P4-17、P4-18）
- **UI 测试**（`@yuriai/ui`）：Host Runtime Registry 的 Location Key 解析；侧边栏远端角标、hover、离线态和移除态；同名项目并存；输入框机器 chip 与离线禁止发送；本机专属操作被禁用；手机网页和 VS Code 的不支持分支；多窗口通知去重。可参考的现有测试：侧边栏项目列表性能测试、侧边栏操作性能测试、会话归属测试。
- **性能操作计数测试**：扩展输入框 closed picker 测试（P2-9）；新增跨 host 事件不扇出测试（P1-5、P1-7）、无远端项目时零新增工作测试（P0-1）、transcript SSE 性能测试的多 host 并发变体（P1-6）。
- **实测**：用 Electron 生产构建和 iOS 模拟器（`serve-sim`）对 P0-2、P1-4、P2-8、P3、P4-18、P5 计时。脚本放在 `.scratch/remote-projects/`，沿用 `.scratch/long-chat-performance` 的 probe / replay 方式。
- **迁移测试**：旧版的项目数据和持久化状态升级后，本机项目的 Location Key 能命中原有的草稿、tab、会话窗口状态和会话顺序，没有任何数据丢失。

## Out of Scope

- 手机网页和 VS Code 上的 Remote Project 能力（只显示不支持提示）。
- 多级聚合。
- 在 Remote Project 中修改远端机器的机器级配置（Provider、插件、MCP、主题、设置），这些仍通过整窗切换完成。
- 本机与远端之间的配置同步扩展。
- 远端 GUI 插件 tab、远程桌面、助理、定时任务在 Remote Project 内的嵌入。
- 会话在不同机器之间迁移。
- Hub 转发远端机器的手机推送。
- 移除整窗切换。

## Further Notes

- 本 spec 的结论来自阅读现有代码：runtime endpoint 是单例；项目实体只有 `path`；session index 表已经带有 `runtime_key`，但调度只认当前 runtime；桌面 host 已具备 `apiUrl` / `clientToken` / `relay`；SSH 管理和设备列表在 Electron 主进程，Relay 隧道客户端在渲染进程。尚未做原型验证。
- 最大的两项风险：一是把以 directory 为 key 的状态全面迁移到 Location Key（涉及 sync、stores、草稿持久化）；二是把远端连接能力下沉到 server 侧的 Remote Host Gateway。
- 建议的工单顺序：
  1. Location Key 与迁移：本机零行为变化，P0 先达标。
  2. Remote Host Gateway 下沉到 server，以及 `GET /api/hosts`。
  3. 多分区 session index、状态订阅、侧边栏只读展示、双写创建项目。
  4. 远端会话的打开、发送、权限，内容订阅，客户端缓存。
  5. 整理信息写回。
  6. 输入框目录、文件、git、终端、预览代理。
  7. 移动端，以及通知去重。
- 落地前补充 `CONTEXT.md` 中的术语（Hub、Remote Host、Remote Project、Location Key、Host Connection、状态订阅、内容订阅），并为“聚合与整窗切换并存、远端为权威、Hub 不存内容”写一份 ADR。

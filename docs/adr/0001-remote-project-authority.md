# Remote Project 由当前实例聚合，远端保留权威

同一个窗口需要同时管理多台 PC 上的项目，并让手机复用当前所选 PC 的视角。采用当前 PC 实例作为 Hub 的一级聚合，与原有整窗切换并存：整窗切换改变 Hub，Remote Project 只关联目标项目；手机不建立第二套聚合目录。

项目先在远端确保存在，再在 Hub 保存引用和显示布局；项目元数据、会话内容及会话整理信息以远端为准。Hub 仅持久化摘要与状态快照，不持久化远端聊天内容；客户端可保留隔离、可失效的加速缓存。失败时不把未知当空，不把失联当停止，写回失败不得制造永久本地分叉。

客户端在线期间共享轻量状态订阅，查看内容时按需增加内容订阅。这样能发现其他窗口启动的远端会话，同时把后台流量限定为必要状态；无客户端需求时释放订阅。跨机器的同名目录、会话 ID 和异步响应必须隔离，整窗切换不能作为项目级路由的实现手段。

## 取舍

- 不采用各客户端独立聚合：那会分散凭据、重复同步目录，使手机与 PC 视角不同。
- 接受 Hub 不可达时其聚合视角不可用；用户仍可整窗切换到已配对的目标实例。
- 不递归展开对方的远端项目，避免循环和隐含授权链；远端权限在每次服务端请求上校验。
- 范围及可验收指标见 [Remote Project spec](../specs/remote-projects.md)。本文是已确认的设计决策，不是实现完成声明。

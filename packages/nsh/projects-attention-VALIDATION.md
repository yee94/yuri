# Projects blocking attention

## Authority and ownership

- `projects-attention-blocking.ts` owns Location-scoped pending request snapshots inside the existing Host/generation attention scope. Rows make no requests and subscribe to no new event streams. Historical messages, notifications and viewed/unread state cannot create or remove a block.
- The existing `state.ts:observeRuntime` attention seam now injects `request` and a captured-key/current-generation check. Its lifecycle effect calls `setActive` after the sole root listener has subscribed; relevant root events rebind the active source before `accept`. `createChat`, `application.tsx`, deletion/Undo and `projectsInProgress` semantics are unchanged.
- Initial foreground activation, resume, `reconnected`, `server.connected` and `global.disposed` read `GET /api/debug/location`, then `GET /api/form?location[directory]=…` and `GET /api/permission/request?location[directory]=…` only for live Locations. Two directory workers bound actual domain requests to four. There is no per-row request, extra SSE, timer or historical-directory boot.
- Question forms require `metadata.kind === "question"`, just as Web. `form.created/replied/cancelled`, legacy question events and `permission.asked/replied` update exact session/request identities. A resolved ID is not cleared by viewing a chat; only unread is. In-flight GETs overlay exact changed IDs rather than dropping another request in the same session.
- Failed inventory/domain reads preserve prior positives and mark completeness unknown. An identifiable malformed session preserves only that session; complete siblings still reconcile. Empty success clears only its own authoritative domain. Retirement, background suspension, move events, missed-move snapshot recovery and Location shutdown fence stale results.
- `projects-attention-indicator.tsx` uses the real Web `resolveMobileSessionIndicator` order via `projects.tsx`: question → permission → running → unread → idle. Question/shield reuse the existing sprite; the busy ring matches `SessionBusyIndicator` geometry. Status colors and all four accessible labels reuse existing theme and ten-language dictionaries. No product UI or setting is added.

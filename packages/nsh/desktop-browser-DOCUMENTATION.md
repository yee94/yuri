# Independent native workbench browser

## Ownership and registration

`desktop-browser.tsx` is a normal panel child, never an application root, Sheet or full-screen route. The shell owns browser/preview tab identity and supplies the captured `DesktopPanelScope`, `current`, `active` and optional initial `intent`. `request={fn => …}` registers that exact tab's `request(intent)` handle; a retired child cannot unregister a newer handle. HTML uses `{kind:'preview',path}`; addresses use `{kind:'browser',url}`. Same-tab navigation keeps one native component. `authorityKey`, Host, lease, session and directory all participate in remount identity. GUI plugins/Eficy/TSX execution are excluded.

Required integration points (entrypoints are intentionally not edited by this module):

1. Add `mod browser_view;` in the Rust runner. Construct one `browser_view::Port::new(network.clone())` and give clones to the connection actor and native UI.
2. After committed selected-connection restoration or a durable connection transition has issued its new scope, call `port.authorize(&scope, &connection.url, &connection.token, allow_loopback)`. This requires a native device bearer; an unavailable browser authority must not undo a valid connection commit. Never expose this API to JS. Revoke with `port.invalidate()` before changing/removing the native lease, and on shutdown.
3. macOS: after `AppView::new`, **before** `view.load`, keep `let mut browser = browser_view::macos::register(&view, port, mtm);`. Call `browser.poll()` from the existing UI-thread timer. Keep the pump alive until AppView teardown.
4. Windows: before `run_app`, call `browser_view::windows::register(&options.components, port)`. Each child HWND owns a UI-thread Win32 timer; no inaccessible internal AppView is needed. NSH moves/clips/hides the child window with the panel. Like all HWND content, it is above NSH drawing: hide it when a shell overlay covers that panel.
5. Panel/browser and file-preview tabs render `NativeDesktopBrowserPane`; no extra Host capability or `resources.web.present` full-screen desktop fallback is needed. The intent grammar and captured-owner protocol reuse the iOS resource preview boundary; iOS implementation remains unchanged.

No dependency or Cargo manifest changes are required. macOS uses public NSH objc2/AppKit/Foundation reexports plus WebKit system selectors. Windows uses NSH's public `HWND`/Components and the WebView2 system COM ABI; its loader is the same `WebView2LoaderStatic` already linked by NSH 0.4. The public Environment10 ControllerOptions API must support **InPrivate**; otherwise creation fails explicitly. No builtin NSH WebView is used because NSH's builtin Windows WebView injects `window.nsh`.

## Trust and lifetime

- Only the native connection actor supplies origin/bearer. Web pages and NSH JS receive neither. Each component command is matched against exact owner, Host+lease and generation. A shared native epoch revokes old requests synchronously; a bounded, never-evicted owner admission set prevents delayed remount/reuse. Close affects only its exact component, including after its Host has retired.
- Host HTML stat/read uses `/api/fs/stat` and `/api/fs/serve`, never the client filesystem. Entry documents are HTML, resources are canonical and directory-contained. Browser addresses naming localhost/127.0.0.1/0.0.0.0/[::1] are Host intents: native POST `/api/preview/targets` with the existing `X-Yuri-Native-Preview` protocol, exact five-minute TTL and `allowExternal:false`. They never call the client's localhost.
- Short-lived preview target tokens stay in native memory and request headers. The existing Host rewriter may put an old target token in resource URLs; native routing strips it and uses only its captured header token. The address bar never publishes that query. Long-lived bearer credentials never enter any URL.
- macOS uses a private `yuri-resource://<owner>/…` scheme. Windows intercepts every request to a per-owner virtual `https://<owner>.yuri-preview.invalid` origin with `WebResourceRequested`/deferrals and serves native responses. Only canonical routes inside that captured directory/target can reach authenticated Host HTTP. Redirects, stale generations, oversized responses, unsafe schemes and off-origin native credential use fail closed.
- Resource responses preserve Content-Type and upstream CSP, add restrictive CSP, no-store/no-referrer/nosniff and omit Cookie/Set-Cookie. They permit only same-resource GET subresources; no frames, workers, forms, external networking or websocket/HMR tunnel is provided. These restrictions match the narrow iOS resource renderer, not a full devtools/browser runtime.
- External HTTP(S) pages use the engine's ordinary network with **no Host authentication**, no app scripts, message handlers or native host objects. Client loopback subresources are blocked, not redirected to the client's dev server. macOS uses a per-component nonpersistent WKWebsiteDataStore; Windows uses a distinct InPrivate owner profile. These are intentionally not the user's real browser sign-ins. Resource proxy cookies are never forwarded to Host; authenticated/cookie-dependent dev apps can therefore fail explicitly.
- Target expiry is an error, not indefinite credentials. Reload can reacquire a target. Native history can revisit retained in-scope documents while their target lease remains valid. Expired target-history entries are not silently elevated to a new Host. Hiding cancels native resource reads/current navigation; showing reloads the current semantic URL. External WebKit page timers are not proven suspended by stopLoading; this is not a claim of background script suspension. A native scope change disposes the old surface.
- HTTP response limit is 8 MiB, 32 MiB accepted bytes per load, 8 resource reads and 256 requests. NSH fetch cancel suppresses callbacks but cannot physically interrupt an already-blocked OS read; this module does not claim otherwise.

## Evidence and gaps

- Focused Vitest tests cover URL validation, localhost proxy intent, same-tab no-op/change, old generation events, exact cleanup and inactive admission. The NSH 0.4 headless fixture exercises the real Input/toolbar/component mount and `authorityKey` remount without pretending to render a webpage.
- `examples/browser_contract.rs` compiles/tests the module independently of the runner's concurrently edited entrypoints. Its eight Rust tests include route/token/cookie/redirect/response-limit and captured-authority isolation. `--native` uses only an injected synthetic Network, never bridge installation or Vault. A real AppKit run loaded HTML + CSS in WKWebView, emitted ready and retired on authority invalidation. Do not run that window during another agent's screenshot/keyboard work.
- macOS module passes Cargo check/clippy. The native smoke preceded the final history/refresh refinements; those refinements have only static/contract evidence until the next permitted AppKit run. Back/forward, external browser opening, failure/cancel UI, real proxy transport and layout/occlusion still need platform acceptance.
- Windows has a real child-HWND/WebView2 implementation, not a capability-only gate. Its raw interface IID/method offsets were checked against the public WebView2 binding definitions. An isolated ABI/type harness passes; that harness substitutes only NSH platform signatures and **is not a Windows-target build**. A real Windows check was blocked by uncached `byteorder-lite`; this Mac has no Windows Rust std/SDK. Windows linking, COM callbacks, HWND geometry, InPrivate behavior, browser history, expiry refresh and real rendering remain **unverified**; do not call it feature-complete.
- Package `nsh:check` currently stops at existing shared `ui/src/lib/relay/tunnel-client.ts` ArrayBufferLike errors, with no browser-file error. `dead-code` stops loading existing web Vite config because `vite-plugin-pwa` is absent. No dependency was installed to bypass those blockers.

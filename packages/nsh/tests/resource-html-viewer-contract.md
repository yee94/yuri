# HTML viewer — production assembly contract

## Contact attachment generation admission

`ResourceBridge.ContactAttachmentResource` accepts only the existing contact envelope and descriptor keys plus optional `generation`. A present generation must be a nonnegative safe integer (0 through 9007199254740991); bool, array, null, string, negative, fractional and unsafe values reject before transport capture. Only an absent field uses the existing legacy wire. No default generation or runtime-lease substitution is permitted. The typed value retains assistantID, attachmentID, SHA-256, size, MIME, optional filename and optional generation, and reconstructs the canonical descriptor without refreshing any identity field. `resources-request.ts` already forwards that canonical descriptor and needs no production change.

The frozen Host contract remains `GET /api/yuri/assistants/:id/contact/attachments/:attachmentID` with the original runtime authentication, no new query/header/endpoint. Host's `assertContactAttachmentReadable` enforces assistant, live generation and non-retired row; the already-owned-turn materialization path cannot authorize a new preview. For descriptors with generation, the same captured transport reads the existing `contact/messages?limit=1` top-level generation before and after the raw GET, bounded to 1,000,000 bytes, and once more before publishing a lease after asynchronous image/media preparation. HTTP/JSON/integer errors fail closed. Raw bytes must match exact status, size, MIME and SHA-256. A reset observed by those checks rejects admission; these bounded snapshots do not create an atomic Host transaction or promise continuous revocation of already displayed content.

Every new contact preview/save/share presentation, including legacy, reuses the lease's original descriptor and captured authenticated transport to re-read and verify the original bytes (limit = descriptor size). Generation-aware descriptors repeat their generation checks. Legacy issues only the original raw GET, with no generation metadata request, query or default, and relies on Host current-generation admission. This intentionally prevents a cached legacy original from granting new presentation permission after reset. The recheck does not replace the lease or rewrite its cached file. After the await, the exact lease URL must still exist in the original map and the transport must remain current; releasing the lease during recheck prohibits a late window and does not retire a peer or source file. Failures retain the old displayed resource and can be retried through its existing owner.

`resource-contact-generation.test.ts` executes the production Swift parser/read policy and extracted actual present/close/release methods against controlled platform boundaries. It covers full TS-to-Swift new/legacy wire identity, strict invalid generation/unknown keys, descriptor tampering, reset during GET, Host/row staleness, and exact release during pending reauthorization. `resources-request.test.ts` also checks invalid values reject before native invocation. Complete real SDK checks remain separate; system window behavior, Photos/provider originals, long-image fidelity and PDF reading require main's UIKit acceptance. The build-only synthetic carrier and exact operations are in `contact-resource-uikit/README.md`.

`resources.tsx` consumes the display/controller ports through `resource-html-native.tsx`. `ResourceWebPreviewView.swift` supplies the actual shared HTML UIView carrier; `ResourceHTMLComponents.swift` registers that component and the exact Dialog presentation anchor. This assembly has pure JS tests and real SDK compilation evidence. Runtime/UIKit/real WK acceptance is separately owned by main and is not inferred from those checks.

It must construct the viewer once per file owner, not inside `busy`, error, content kind, stat or content-lease conditional branches. ## Lifecycle

Inline preview → fullscreen: await exact inline close → retain Dialog generation → actual `Dialog.onOpen` → reserve fullScreen mount. Source mode enters fullscreen without creating WK. Both directions preserve mode; returning inline may remount WK, as the Web portal does. No JS heap, scroll or in-page state retention promise.

FullScreen Back → exact WK close → `Dialog.open=false` → **actual `Dialog.onClose` for that generation** → remove dialog root → reserve inline mount if still eligible/active. Repeated opening/closing shares one flight. Late `onOpen`, `onClose` and generation-scoped Back cannot affect a new dialog. The local `NavStack`/`NavPage` owns the real system header; headerLeft Back and headerRight contain only actual actions, not a custom imitation header.

Close failure retains the old mount/identity/scope, keeps the Dialog open where applicable, displays the existing localized preview-unavailable message and explicit retry. No update, mode switch or new identity can create a fresh mount until retry succeeds. `dispose()` rejects on close failure, and successful fullscreen disposal waits for both WK retirement and actual Dialog close; parent must preserve its root for retry/completion. The cleanup callback only makes a best-effort disposal request and is not a replacement for parent-owned awaited teardown.

System save/share sets the controller's presentation-pending gate before native invocation. Back, mode switches and fullscreen dismissal remain locked through the native operation's real dismissal completion. External invalidation closes the original lease; source-mode Dialog teardown also waits for presentation settlement. Native completion callbacks carry their exact presentation ID so a delayed old dismiss completion cannot finish a newer system window. Native WK failure is observable and requires explicit retry; old failure events cannot change a replacement mount.

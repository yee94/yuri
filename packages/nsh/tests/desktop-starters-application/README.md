# Desktop starter production-root evidence

`Root.tsx` mounts `YuriNativeApp` without injected routes, controllers or widgets. `Host.js` extends the strict navigation Host with only synthetic starter settings GET/PUT; every create, prompt and unrelated mutation remains rejected. It does not access real credentials or accounts.

The independent temporary wrapper runs macOS/Windows headless models, two scenarios each: native pan release reorders once while retaining the draft, and hover removal does not activate a starter. It also checks desktop plus/no mobile trash, fifty input edits with no additional reads, and Settings cover/close retaining the draft. These four production-root scenes are not four OS windows or physical mouse tests.

`new-session-starters-drag.test.ts` separately exercises actual production callbacks with synthetic measurements: >8pt mouse activation with no hold timer, 200ms/6pt mobile boundaries, exact release translation, one pending measurement, duplicate release, modal/Host retirement/cancellation, wrapping unequal widths, collapsed AX admission, per-group ordering/removal and a 128-chip operation budget.

The fixed NSH 0.4.0 test `drag` API supplies a finger/pan sequence, not a physical desktop mouse stream. Its release validates production assembly; live mouse move dispatch is tested through the real component callback separately. NSH's public raw touch DTO has no pointer-kind field; the desktop touchscreen delay sensor remains unresolved. AppKit/Win32 drawing, physical input, accessibility and timing budgets are not signed off by these tests.

# Settings operation recovery evidence

`SettingsBasics` keeps its editor/Scroll, data, dirty changes, prompt, selections and Voice confirmation controller mounted. `settingsOperationLifetime` replaces only the explicit `SettingsOperation`; asynchronous callbacks receive that exact object, including its sender/transaction and assigned-object fence. Retirement clears only its old flight ownership. A late finally cannot release a replacement lane's busy state.

`settingsPageLifetime()` applies the same explicit operation model to Archive, Collections, Defaults, Git, Integration, Magic Prompts, MCP, saved permissions, plugin runtime, Preferences, Projects, Providers, skill files, Usage and Retention, including the MCP import draft. It observes confirmed root authority, permanently retires a different Host/origin/authorization identity, and preserves its operation during ordinary route cover. A replacement notifies retained controllers; each asynchronous function/perform callback receives its captured operation. The old `settingsLifetime()` API remains available for independent consumers, but no page in this owned group aliases its constructor sender anymore. There is no latest-sender proxy.

`createSettingsLaneOwner` is the pure retained-controller seam. `capture()` returns a fixed sender and assigned-object fence; `replaceLane` invalidates old captures without discarding controller data. Archive retains pending verification keys; Provider removal retains its original consent and per-target attempts/ACK progress; Project settings retain baselines, dirty sections, pending file submission, edit revisions and command IDs; Usage retains selected provider and preference intent; Retention retains preferences and its journal. New lanes clear only old flight ownership and recover through reads. Existing timers capture their original revision/lane. Project auto-save is rearmed by a subsequent edit, never by foreground replacement.

An uncertain custom Provider create retains `creationAttempted` before dispatch. Without an authoritative receipt linking the generated providerId/credential to that request, Save retry only reads the catalog and retains the key/draft; it cannot create another instance or infer a successful credential write. Magic reset/all GET reconciliation completes draft cleanup by captured edit revision, preserving later edits even when text is identical.

Voice confirmation's `replaceLane` retains the pending patch, edit revisions, acknowledged/unknown status and local draft. Foreground refresh performs GET even when a journal is pending, merges retained edits, and does not clear or certify that journal. Only explicit confirmation reconciles it. An uncertain credential remains unknown when public configured flags cannot prove its replacement; it is never automatically written again. Lane replacement invalidates read sequences and gives new work its own busy token.

Recognition creation waits for old adapter disposal and existing tester Native flights/stop/release. Cleanup failure blocks new capabilities and uses the existing explicit retry action to retry only the failed old audio identity. Replacement adapters capture the new operation's exact scope. Each transient tester gets fixed operation/current/confirm/adapter/call closures; only `voiceTestVersion` changes, not the editor's key. A missing lease remains read-only and cannot admit Voice testing.

## Main integration

- Keep the mounted `SettingsBasics`/Settings route and its `active` display gate stable for same-Host foreground. Do not key the editor/route on epoch or keep passing a constructor epoch gate as its active state.
- Optional narrow prop: `operationToken?: ReturnType<typeof captureHostOperation> | null`. Publish null on suspension; publish a newly captured object only after the root's confirmed foreground snapshot. Forward it without copying an old value into a static constructor field. If omitted, Basics observes adopted runtime scope/readiness via `captureHostOperation()` itself; it never calls `loadConnections()` for Voice recovery.
- The mounted Host id/origin/authorization identity is permanent. A confirmed different identity retires the editor even after A-B-A. A null suspension scope does not mean Host change.
- `SettingsVoiceModels` now owns a retained model manager and its own captured operation. Basics passes the stable display gate and editor callbacks, not a frozen initial sender. Manager replacement preserves model/progress/error data and per-model attempted/acknowledged receipts, and only GETs status. Ambiguous download/delete is not replayed; an explicit `{ok:false}` rejection releases that receipt for a subsequent user retry. A delayed delete confirmation checks its original manager lane before mutation. No model-manager/editor remount is used.
- Raw GitHub/Git credential/About surfaces and quota credentials belong to their separate owners. This change does not edit their production files or alter raw-response parsing. Their parent routes must likewise remain stable and publish confirmed operation authority; shared-page adoption must not be interpreted as a replacement for their own retained-controller seams.

## Validation boundary

`settings-voice-operation-recovery.test.ts` executes actual production page callbacks, lifetime, confirmation controller, recognition adapter, request binder and the extracted original state operation factory with inert JSX and strict synthetic Native ports. It covers root snapshot gap, explicit-token and observer paths, same-lease generation renewal, retained edits/model selection, ACK/unknown journals, late reads/finally/capabilities, cleanup ordering/failure retry, read-only legacy mode and permanent A-B-A retirement. The shared fixture additionally executes Collection, Integration, Archive, Project and download-manager surfaces across foreground, checking unchanged Scroll/command row identity, exact long drafts, secret cleanup, request scope and read-only recovery. Provider creation has a delayed POST/foreground/Save-retry regression proving one POST and retained key.

`settings-controller-lane-recovery.test.ts` exercises retained Magic, Project, Usage, Retention, Archive and download controllers through replacement lanes. It includes reset/all finalization, identical-value later edits, acknowledged setup with newer commands, unknown download refusal, and explicit rejected-download retry. The independent same-model read-only review found the Provider creation, rejected-download receipt and Magic reset-finalization defects; all three have corresponding fixes and focused regressions, and the reviewer reread those fixes.

The actual `SettingsPage` forwarding regression starts with an explicit null operation: no Voice GET/capability is allowed until root confirmation, then the same mounted Basics receives authority and later foreground renewal retains the secret draft. `SettingsPage` declares and directly forwards `operationToken`/`active`. This pure fixture models dynamic JSX attributes; it is not evidence for the application's separately owned route wrapper. That wrapper must supply live authority rather than evaluate it once in an ordinary object literal.

`native-select-contract.test.ts` exercises the iOS selector's production callbacks with inert JSX: controlled value/open getters, normalized disabled entries, title search, custom item/group renderers, selected state, clear, lifecycle callbacks and popup/backdrop style forwarding. Input comes from `nsh/base`; nullable search labels/placeholders normalize to undefined, and no unsupported Button accessibility state is asserted. Installed declarations define those contracts. NSH source `nsh-js/src/dom.rs` preserves descriptors in `merge` and follows leaf spreads in a render effect; `components.rs` tracks registered component and host properties and holds JSX slots separately. Consequently ordinary component prop spread alone is not evidence of lost reactivity or an invalid Select title leaf. Sheet geometry and the non-iOS Select's actual native rendering still require main's runtime validation.

This is pure JS evidence. It does not execute NSH, UIKit, microphone, Keychain, a real Host or an engine fixture. Main owns the serial Voice engine rerun and stable navigation/display gate integration. No successful engine or device result is claimed by this task.

# Session goals

Yuri displays OpenCode's native Goal state. OpenCode owns the objective, review, continuation and limits; Yuri does not run a separate goal loop.

## Start a goal

Enter `/goal <objective>` in a project session, review the text, then send it. Selecting `/goal` from autocomplete only inserts the command. A bare `/goal` displays the current goal's reason; it does not arm a new goal.

Write a self-contained outcome with verification criteria, up to 4000 characters. For example: “Fix the failing parser case, run its tests, and report the command and result.” Plan and answer dialogs and [scheduled tasks](/scheduled-tasks/) can also run as a goal through the same native command.

## Status and controls

The strip above the input shows the objective, native status and continuation count. Open its details to read OpenCode's reason. States are active, paused and complete. The Chat display setting affects visibility only; shared Goal UI is available in web, desktop, VS Code and mobile.

- `/goal pause` pauses automatic continuation; it does not interrupt work already running.
- `/goal resume` resumes a paused goal.
- `/goal clear` removes the goal without interrupting the current turn.
- Use the session's Stop action to interrupt current work.

Yuri adds no Token budget, objective distillation or question-triggered pause. OpenCode determines when to continue or stop. Verify completion against the actual files and results.

## Execution ownership

Closing a browser tab does not stop the OpenCode service. Keep that service available for execution. Old Yuri goals are not imported or resumed automatically; create a native goal to continue them. Use a scheduled task for recurring work, not a single goal as a timer.

# 会话目标

Yuri 只展示 OpenCode 原生 Goal。目标、评估、自动继续和限制均由 OpenCode 管理，不再运行另一套目标循环。

## 开始目标

在项目会话输入 `/goal <目标>`，检查后发送。从命令列表选择 `/goal` 只会插入命令。单独发送 `/goal` 会展示当前目标的原因，不会准备新目标。

目标最多 4000 字符，需写清结果和验证标准。例如：「修复解析器失败用例，运行对应测试，报告命令和结果。」计划、回答派生会话和[计划任务](/zh-cn/scheduled-tasks/)中的「作为目标运行」也走同一个原生命令。

## 状态与控制

输入框上方显示目标、原生状态和继续轮数；打开详情可查看 OpenCode 给出的原因。状态只有进行中、已暂停和已完成。聊天设置只控制显示，不控制执行；Web、桌面、VS Code 和移动端共用这套目标界面。

- `/goal pause` 暂停自动继续，不会中断已经运行的工作。
- `/goal resume` 恢复已暂停的目标。
- `/goal clear` 清除目标，不会中断当前轮次。
- 需要中断当前工作时，使用会话的停止按钮。

Yuri 不再附加 Token 预算、目标蒸馏或遇到问题自动暂停的逻辑，由 OpenCode 决定何时继续或停止。完成状态仍需结合实际文件和执行结果核对。

## 执行归属

关闭浏览器标签页不会停止 OpenCode 服务；执行期间需保持该服务可用。旧 Yuri 目标不会自动导入或恢复，需要继续时请创建原生目标。周期工作使用计划任务，不要把单个目标当定时器。
